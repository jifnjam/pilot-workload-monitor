
# Pilot Cognitive Workload Monitor

A neuroergonomics project: classifying cognitive workload level (low / medium / high) from and EEG headset, using signal processing techniques, cross-validated two different ways, cross-checked against MATLAB, and demonstrated through an interactive GUI.

Built as a portfolio project connecting neuroengineering and aviation — the target framing is a pilot workload monitor, evaluated on a controlled N-back cognitive-load task.

## What this actually does

- Loads raw EEG (Emotiv EPOC X, 14 channels, 128 Hz), filters and epochs it, with every preprocessing choice grounded in the specific hardware's documented behavior
- Extracts band-power features (theta, alpha, beta-low, beta-high, gamma) per channel, matching this headset's own onboard band structure
- Cross-checks Python's feature computation against MATLAB's `bandpower()` and runs a one-way ANOVA in MATLAB on the full feature set
- Trains and evaluates **two models answering two different questions**: a cross-subject model (works on a pilot it's never seen, ~38% accuracy) and 16 within-subject personalized models (works on a pilot with some of their own labeled data, ~95% accuracy) 
    See `docs/project_writeup.md` for why that gap exists and what it means
- A CustomTkinter GUI that loads a recording, animates through it with live predictions, includes a working prototype of on-the-fly personalized calibration, and shows model performance

**Full methods, results, limitations, and a complete development log (including every real bug hit and how it was diagnosed) are in [`docs/project_writeup.md`](docs/project_writeup.md). Please read that for anything beyond "how do I run it."**

## Setup

1. Clone this repo and create a virtual environment:
   ```bash
   python -m venv venv
   source venv/bin/activate   # Windows: venv\Scripts\activate
   pip install -r requirements.txt
   ```
2. Download the dataset (no account needed):
   ```
   https://ddd.uab.cat/pub/dadrec/2022/259591/workload_dataset.zip
   ```
   Unzip it into `data/raw/`.
3. (Optional, for the MATLAB validation step) MATLAB with the Statistics and Machine Learning Toolbox installed. If you also want the live MATLAB Engine API integration rather than just the file-based one, see the setup steps in `docs/project_writeup.md`'s Methods section.

## How to run it

Run the notebooks in order — each one depends on the previous step's output:

1. `notebooks/01_explore_raw_data.ipynb` — confirms the dataset's structure
2. `notebooks/02_preprocessing.ipynb` — filters and epochs the raw EEG, saves `data/processed/*-epo.fif`
3. `notebooks/03_matlab_integration.ipynb` + `src/matlab_bridge/matlab_scripts/compute_stats.m` — the Python/MATLAB cross-check
4. `notebooks/04_feature_extraction.ipynb` — builds `data/processed/full_features.csv`
5. `notebooks/05_model_within_training.ipynb` (within-subject) — trains and evaluates the model(s), saves `docs/metrics.json`, and the figures in `docs/screenshots/`

Then launch the GUI:
```bash
python gui/app.py
```

`scripts/run_pipeline.py` checks that every notebook's output already exists and launches the GUI. It is more so a convenience runner, not a replacement for actually running the notebooks.

## Reminder before digging into the code

`04_feature_extraction.ipynb` and `gui/app.py` each maintain their **own independent copy** of the feature-extraction logic (band definitions, the frontal ratio calculation) rather than sharing one module. They were kept in sync by hand throughout development. Checkout the `docs/project_writeup.md`'s Appendix for a real bug this exact kind of duplication already caused once. Consolidating into a shared `src/features.py` is one of the future work goals.
